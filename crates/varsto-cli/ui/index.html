      Guides

      Welcome to Varsto

      Create a new vault, join one of your existing vaults, or accept a folder that someone shared with you. Everything is encrypted on this device before it reaches any storage.

      Create a new vault here if this is your first device. If you already use Varsto, choose Add a device under Devices on your other device and type the code it shows.

      Pair with your other device

      On a device that already uses Varsto, open Devices and choose Add a device. Type the code it shows, or scan its QR code.

      The other device is not found

      Create a new vault

      You will be shown the vault key once. Write it down and keep it offline; it is the only way to add other devices or recover the data.

      Join with the vault key

      The secret is kept in this device's encrypted secret store, never in a plain file.

      Join your organization

      Step 1: send an administrator the request code from this device. Step 2: read its six-word fingerprint to them over a call or in person; they see the same words. Step 3: paste the approval token they send back.

      
        
        
      
        
      The token carries the vault key and the storage settings, sealed to this device's request key; only this device can open it.
      
      
      
      
      
        
      Accept a shared folder
      
        
        
        
      Step 1: send the owner a request code from this device (it carries the device name above). Step 2: read its six-word fingerprint to the owner over a call or in person; they see the same words. Step 3: paste the sealed token they send back.
      
        
      
        
      
        
      
        
        
      
        
        
      
        
      
          
          
          
          
          
          
      Credentials the owner gave you for this bucket. The secret is kept in this device's encrypted secret store.
      
        
      
        
      
        
      You get the folder key only: this device can read and write that folder, nothing else of the other vault. A sealed token (vst1… or vst2…) can be opened only here, and this device checks that the owner confirmed its fingerprint; a plain token carries the key itself.

                Ignore rules

                        Bring files that live elsewhere under Varsto's care. Each source becomes one folder; importing the same source again brings over what changed and never deletes anything in Varsto.

                            Version history
                            
        
                            When a file is overwritten, on any device, its earlier version is kept: every version for an hour, one per hour for a day, one per day for 30 days, then one per week. Unchanged parts are shared between versions, so only the changes take space. Restore a version from the file's details on the Files page.
                            
        
                            
        
        
        
        
        
        
                            
      
                            
    
                            

    
    
                            
      
                            
        
        
                            Durability policies
                            
        
                            A policy states how many copies a folder must have, where, and how recently another device must have verified them. Varsto checks it against the ledger on every sync and tells you before a rule is broken.
                            
        
                            
        
                            0 means no rule; a row of zeros removes the folder's policy.
                            
        
                              
        
                              No folders yet
                              Policies are set per folder.
                              
      
                              
      
                              
        
                              Automatic verification
                              
        
                              The background service downloads, within a budget, blocks that other devices wrote, checks their hash and records the check in the ledger, so "verified by another device within N days" stays true. Cold storages and transferrers are never read; nothing runs while the service is paused or locked.
                              
        
                              
        
                              
      
                              
      
                              
        
                              Automatic repair
                              
        
                              When verification or a storage check finds a block missing or damaged on one of your storages, the service writes it again from another copy: another storage, this device's files or encrypted blocks, or a peer. Cold storages are read only when you ask; transferrers are never written.
                              
        
                              
        
                                
        
                                
      
                                
      
                                
        
                                Bit-rot check
                                
        
                                Stored data can decay without anyone noticing. The background service re-reads, within a budget, every block on your storages and attached disks, whoever wrote it, and every synced file on this device, so that everything is checked at least once in the period. A damaged block is repaired from another copy. A file on this device that changed without being edited is never overwritten: it is moved aside as name.damaged-date and the synced version is put back. Cold storages are read only when you include them.

                                            Device platforms that may join and open the vault
              
              
              
              
              
              A device of another platform is refused at approval; one already in the organization is locked out (no new keys, the other devices ignore what it writes, its own app does not open the vault) until its platform is allowed again. Devices say which platform they run, so this binds honest apps, not a modified one. It applies to administrators' devices too.
