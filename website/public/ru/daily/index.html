Ежедневные сборки

Это сборки для разработки из основной ветки, не выпуски.

  • Это не выпуски, и тестирования выпуска они не проходили. Подписи выпуска нет, подписи кода Apple и Microsoft нет. Не используй их для рабочих данных.
  • Формат хранения может смениться от сборки к сборке без миграции. Эти сборки пишут формат хранения 3: хранилище, созданное 0.0.1-alpha.15 или раньше, отклоняется, и его надо создать заново (varsto reset --yes, varsto init, затем снова синхронизировать файлы), а 0.0.1-alpha.15 отклоняет хранилище формата 3. Устройство, которое присоединяется, запрашивает каждую папку, и владелец подтверждает запрос. varsto init печатает второй набор из 24 слов восстановления, которые затем спрашивает varsto folder add.
  • varsto update --daily ставит новейшую ежедневную сборку твоей платформы (командные сборки Linux и Windows; приложение macOS и Android-APK ставятся вручную). Обычный varsto update остаётся на выпусках и никогда не ставит ежедневную сборку.
  • Ежедневная сборка Android — debug-APK (varsto-daily-android-debug.apk), а APK выпуска подписан другим ключом, поэтому ни один не обновляется поверх другого: удали один, прежде чем ставить второй. Это удаляет копию хранилища на этом устройстве.
  • Храни свои резервные копии.

Нужно то, на что можно опереться? Возьми вместо этого стабильные загрузки.

Проверка

Положи SHA256SUMS рядом со скачанными файлами (имена в таблице постоянные) и выполни

sha256sum -c SHA256SUMS --ignore-missing

Не указывай --ignore-missing, если скачал каждый файл. Список подписан отдельным ежедневным ключом (SHA256SUMS.sig, формат minisign; ключ — daily-key.pub), и именно его проверяет varsto update --daily. Подпись не только говорит, что загрузка полная и целая: она показывает, что список вышел из собственной сборки проекта.

Известные пробелы

  • У сборок нет подписи выпуска и подписи кода Apple или Microsoft. Список контрольных сумм подписан отдельным ежедневным ключом (его проверяет varsto update --daily). Это показывает, что сборка пришла из CI проекта, а не то, что её тестировали.
  • macOS, Windows и iOS предупреждают о неподписанном ПО; на macOS это правый клик и «Открыть», на Windows — запрос SmartScreen.
  • Установщик Windows прошёл только дымовой тест в CI (установка, обновление, восстановление, отказ понизить версию, удаление), не на настоящей машине.
  • IPA для iOS не запускали на настоящем устройстве. Ставь его через AltStore, SideStore или Sideloadly.
  • Часть строк интерфейса ещё не переведена; они пишутся в журнал.
  • Эти сборки пишут формат хранения 3. Хранилище, созданное версией 0.0.1-alpha.15 или старше, отклоняется, и его нужно создать заново (varsto reset --yes, varsto init, синхронизировать файлы снова); обновления нет. У присоединившегося устройства нет папок, пока владелец не примет запрос.
  • Windows и iOS всё ещё из предыдущей сборки 20261016-316c579; в этом круге их не пересобирали.
  • Срок, после которого отстающее хранилище данных бросают (пакет E), по умолчанию 30 дней.
  • Полноэкранный код Kotlin, Swift и Windows и исправление сопряжения на настоящих устройствах не проверяли.
  • Первое обновление через --daily требует программу, в которой эта возможность уже есть, поэтому поставь эту сборку один раз вручную; дальше это делает varsto update --daily.
