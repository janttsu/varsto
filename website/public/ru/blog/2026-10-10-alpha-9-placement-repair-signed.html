Alpha.9: данные там, где ты хочешь, починка сама, подписанные обновления и каждая платформа собирается у всех на виду

2026-10-10

Alpha.9 (сборка, которую саму так и не пометили; её изменения вышли в alpha.10) про долгий путь: решать, где лежат данные, возвращать их к тем копиям, которых просит правило, без твоей команды, и доверять обновлению, которое приносит следующую версию.

Данные там, где ты хочешь

У каждой папки теперь может быть размещение: хранилища данных, куда идут её блоки. Данные можно переносить из одного хранилища данных в другое, целую папку или только файлы, которые простаивали сколько-то дней, блок за блоком. Каждый блок записывается на новое хранилище данных и читается оттуда обратно, прежде чем удаляется старая копия, а прерванный перенос просто продолжается, когда его запускают снова. Пул съёмных дисков может просить копии на дисках, которые лежат в разных местах, например один дома и один на работе, и Varsto заполняет каждый диск тем, чего его месту ещё не хватает.

Починка сама

Когда копия пропадает, хранилище данных удаляют или проверка не сходится, устройство, на котором есть данные, кладёт блок обратно туда, куда его хотят правило и размещение папки: из своих файлов, из кэша зашифрованных блоков, из другого хранилища данных или с узла. Очередь починки видна в интерфейсе и через varsto repair.

Подписанные обновления

Список контрольных сумм каждого выпуска теперь подписан ключом выпусков проекта, и этот ключ никогда не покидает машину сопровождающего. Программа обновления отказывается от выпуска, подписанного не им. Она также сверяет контрольную сумму с той, что приложена к выпуску на GitHub: это второй канал. varsto verify-release проверяет загрузку вручную, и minisign тоже. RELEASING.md объясняет схему.

Быстрее от узла к узлу

Скачивания держат одновременно в пути до восьми блоков (на тот момент), заранее забирают маленькие файлы по всей папке и делят одно соединение на узел. Устройство, которое отдаёт блоки, больше не начинает свою полную синхронизацию каждые несколько секунд. Замеры сравнивают Париж, Амстердам и Варшаву, от узла к узлу против бакета S3.

У всех на виду

Каждая платформа теперь собирается и проверяется на машинах GitHub при каждом изменении: пакеты Linux и Windows (пакет Windows проверен на Windows Server 2025, включая пункты меню Explorer), приложение Android в эмуляторе, образ диска macOS и приложение iOS на Apple Silicon. Те же прогоны делают снимки экрана, поэтому картинки на этом сайте идут за новейшей сборкой.

И ещё

Общий доступ записывает, кто просил доступ, по отпечатку, удаление участника переводит общий доступ на новые ключи, и у Strongroom можно сменить ключ. Файлы можно скачать или освободить из файлового менеджера в Linux (Nautilus, Dolphin, Nemo) и в Windows (Explorer). В строке папки остаются две главные кнопки, остальное уходит в меню. Приложение macOS и приложения телефона говорят, когда на странице загрузок ждёт более новая версия, а не называют себя актуальными. Большие партии журнала учёта на S3 больше не отказывают.

Обнови каждое устройство, прежде чем переносить данные

Перенос данных пишет новый вид записи журнала учёта, которую alpha.8 и более ранние прочитать не могут: их синхронизация отказала бы с первого переноса. Сначала обнови все свои устройства. С этой версии неизвестные записи пропускаются, поэтому поздние добавления её не сломают. Клиенты до alpha.8 включительно при обновлении проверяют только контрольную сумму. Этот выпуск первый, чья программа обновления требует подпись.

Всё ещё альфа

Криптографию не аудировали, формат ещё может измениться, и ошибка может уничтожить данные. Используй тестовые данные и храни свои резервные копии.
