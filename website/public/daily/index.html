Daily builds

These are development builds from the main line, not releases.

  • They are not signed and have not been through release testing. Do not use them for production data.
  • The storage format can change from one build to the next without any migration. Format 2 will require vaults to be recreated.
  • varsto update never installs them and never reads this page. To move to a newer daily build, download it again.
  • Keep your own backups.

Looking for something to rely on? Use the stable downloads instead.

Verify

Put SHA256SUMS next to the files you downloaded (the file names are the stable ones in the table) and run

sha256sum -c SHA256SUMS --ignore-missing

Leave out --ignore-missing if you downloaded every file. The list is signed with the separate daily key (SHA256SUMS.sig, minisign format; the key is daily-key.pub), which is what varsto update --daily checks. Besides telling you that a download is complete and intact, the signature shows that the list came from the project's own build.

Known gaps

  • The builds carry no release signature and no Apple or Microsoft code signing. The checksum list is signed with the separate daily key (checked by varsto update --daily), which shows that a build came from the project's CI, not that it has been tested.
  • macOS, Windows and iOS warn about unsigned software; expect right-click and Open on macOS, and SmartScreen on Windows.
  • The Windows installer has been smoke-tested on CI only (install, upgrade, repair, downgrade refusal, uninstall), not on a real machine.
  • The iOS ipa has not been run on a real device. Sideload it with AltStore, SideStore or Sideloadly.
  • Some strings in the app interface are not translated yet; they are logged.
