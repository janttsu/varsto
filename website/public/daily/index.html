Daily builds

These are development builds from the main line, not releases.

  • They are not releases and have not been through release testing. They carry no release signature and no Apple or Microsoft code signing. Do not use them for production data.
  • The storage format can change from one build to the next without any migration. These builds write storage format 3: a vault made by 0.0.1-alpha.15 or earlier is refused and has to be recreated (varsto reset --yes, varsto init, then sync the files again), and 0.0.1-alpha.15 refuses a format 3 vault. A device that joins asks for each folder and an owner approves it; varsto init prints a second set of 24 recovery words that varsto folder add asks for.
  • varsto update --daily installs the latest daily build for your platform (the Linux and Windows command-line builds; the macOS app and the Android APK are installed by hand). Plain varsto update stays on releases and never installs a daily build.
  • The daily Android build is a debug APK (varsto-daily-android-debug.apk) and the release APK is signed with a different key, so neither updates over the other: uninstall one before installing the other, which removes that device's copy of the vault.
  • Keep your own backups.

Looking for something to rely on? Use the stable downloads instead.

Verify

Put SHA256SUMS next to the files you downloaded (the file names are the stable ones in the table) and run

sha256sum -c SHA256SUMS --ignore-missing

Leave out --ignore-missing if you downloaded every file. The list is signed with the separate daily key (SHA256SUMS.sig, minisign format; the key is daily-key.pub), which is what varsto update --daily checks. Besides telling you that a download is complete and intact, the signature shows that the list came from the project's own build.

Known gaps

  • The builds carry no release signature and no Apple or Microsoft code signing. The checksum list is signed with the separate daily key (checked by varsto update --daily), which shows that a build came from the project's CI, not that it has been tested.
  • macOS, Windows and iOS warn about unsigned software; expect right-click and Open on macOS, and SmartScreen on Windows.
  • The Windows installer has been smoke-tested on CI only (install, upgrade, repair, downgrade refusal, uninstall), not on a real machine.
  • The iOS ipa has not been run on a real device. Sideload it with AltStore, SideStore or Sideloadly.
  • Some strings in the app interface are not translated yet; they are logged.
  • These builds write storage format 3. A vault made by 0.0.1-alpha.15 or earlier is refused and must be recreated (varsto reset --yes, varsto init, sync the files again); there is no upgrade. A device that joins holds no folder until an owner approves its request.
  • Windows and iOS are still from the previous build 20261016-316c579; they were not rebuilt this round.
  • The grace period before a storage that has fallen behind is given up (package E) defaults to 30 days.
  • The Kotlin, Swift and Windows full-screen code and the pairing fix have not been verified on real devices.
  • The first update with --daily needs a binary that already contains the feature, so install this build by hand once; after that varsto update --daily can take over.
