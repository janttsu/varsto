Versions quotidiennes

Ce sont des versions de développement issues de la branche principale, pas des versions officielles.

  • Ce ne sont pas des versions officielles et elles n’ont subi aucun test de publication. Elles n’ont ni signature de version ni signature de code Apple ou Microsoft. Ne les utilisez pas pour des données de production.
  • Le format de stockage peut changer d’une version à l’autre sans aucune migration. Ces versions écrivent le format de stockage 3 : un coffre créé par 0.0.1-alpha.15 ou plus ancien est refusé et doit être recréé (varsto reset --yes, varsto init, puis resynchroniser les fichiers), et 0.0.1-alpha.15 refuse un coffre au format 3. Un appareil qui rejoint demande chaque dossier et un propriétaire l’approuve ; varsto init affiche un second jeu de 24 mots de récupération que varsto folder add demande.
  • varsto update --daily installe la dernière version quotidienne de votre plateforme (les versions en ligne de commande pour Linux et Windows ; l’application macOS et l’APK Android s’installent à la main). varsto update seul reste sur les versions officielles et n’installe jamais une version quotidienne.
  • La version quotidienne pour Android est un APK de débogage (varsto-daily-android-debug.apk) et l’APK de publication est signé avec une autre clé, donc aucun ne se met à jour par-dessus l’autre : désinstallez l’un avant d’installer l’autre, ce qui supprime la copie du coffre de cet appareil.
  • Conservez vos propres sauvegardes.

Vous cherchez quelque chose de fiable ? Utilisez plutôt les téléchargements stables.

Vérifier

Placez SHA256SUMS à côté des fichiers téléchargés (les noms du tableau sont les noms fixes) et exécutez

sha256sum -c SHA256SUMS --ignore-missing

Omettez --ignore-missing si vous avez téléchargé tous les fichiers. La liste est signée avec la clé quotidienne distincte (SHA256SUMS.sig, format minisign ; la clé est daily-key.pub), ce que vérifie varsto update --daily. Outre l’intégrité du téléchargement, la signature montre que la liste provient de la chaîne de construction du projet.

Lacunes connues

  • Les versions n’ont ni signature de version ni signature de code Apple ou Microsoft. La liste des sommes de contrôle est signée avec la clé quotidienne distincte (vérifiée par varsto update --daily), ce qui montre qu’une version provient de la CI du projet, pas qu’elle a été testée.
  • macOS, Windows et iOS avertissent à propos des logiciels non signés ; sous macOS, ouvrez par clic droit puis Ouvrir, sous Windows SmartScreen demande une confirmation.
  • Le programme d’installation Windows n’a subi qu’un test de fumée en CI (installation, mise à jour, réparation, refus de rétrogradation, désinstallation), pas sur une vraie machine.
  • L’ipa iOS n’a pas été exécuté sur un vrai appareil. Installez-le avec AltStore, SideStore ou Sideloadly.
  • Certains textes de l’interface de l’application ne sont pas encore traduits ; ils sont consignés dans les journaux.
  • Ces versions écrivent le format de stockage 3. Un coffre créé par 0.0.1-alpha.15 ou plus ancien est refusé et doit être recréé (varsto reset --yes, varsto init, resynchroniser les fichiers) ; il n’y a pas de mise à niveau. Un appareil qui rejoint ne détient aucun dossier tant qu’un propriétaire n’a pas approuvé sa demande.
  • Windows and iOS are still from the previous build 20261016-316c579; they were not rebuilt this round.
  • The grace period before a storage that has fallen behind is given up (package E) defaults to 30 days.
  • The Kotlin, Swift and Windows full-screen code and the pairing fix have not been verified on real devices.
  • The first update with --daily needs a binary that already contains the feature, so install this build by hand once; after that varsto update --daily can take over.
