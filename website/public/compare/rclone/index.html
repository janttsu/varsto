Varsto and rclone

rclone is the command-line tool for copying and syncing files to and from more than seventy cloud storage systems. Its crypt backend encrypts what passes through it, and many people use the two together as a do-it-yourself encrypted backup. Varsto itself can use any rclone remote as a storage.

How rclone works

rclone copies files between a local directory and a remote, or between two remotes: rclone copy, rclone sync (one way, making the destination identical to the source), rclone mount and many more. A crypt remote wraps another remote and encrypts file contents with NaCl SecretBox (XSalsa20 and Poly1305); file names and directory names are encrypted too in its default mode, and can be left in clear or merely obfuscated. Outside a crypt remote nothing is encrypted by rclone. Two-way sync exists as rclone bisync, which keeps a listing of both sides from the previous run and propagates changes in both directions; rclone calls it an advanced command, it has to be set up with --resync first, and files that change during a run may be lost. rclone keeps no record of which copies exist where beyond what each run compares, and has no notion of devices: each machine runs its own commands.

Which one fits

rclone

Choose rclone when you want a mature tool that copies files to almost any cloud on your own schedule, you are happy to script the runs yourself, and one-way copies or a bisync pair are enough.

Varsto

Choose Varsto when several devices should stay in step by themselves, every byte should be encrypted before it leaves, you want a record of where every copy is and policies that warn, and you still want to use the rclone remotes you already have.

Varsto is alpha software: do not trust it with data you have no other copy of, and its cryptography has not been independently audited. The other products here are mature.
