Versions quotidiennes

Ce sont des versions de développement issues de la branche principale, pas des versions officielles.

  • Ce ne sont pas des versions officielles et elles n’ont subi aucun test de publication. Elles n’ont ni signature de version ni signature de code Apple ou Microsoft. Ne les utilisez pas pour des données de production.
  • Le format de stockage peut changer d’une version à l’autre sans aucune migration. Ces versions écrivent le format de stockage 3 : un coffre créé par 0.0.1-alpha.15 ou plus ancien est refusé et doit être recréé (varsto reset --yes, varsto init, puis resynchroniser les fichiers), et 0.0.1-alpha.15 refuse un coffre au format 3. Un appareil qui rejoint demande chaque dossier et un propriétaire l’approuve ; varsto init affiche un second jeu de 24 mots de récupération que varsto folder add demande.
  • varsto update --daily installe la dernière version quotidienne de votre plateforme (les versions en ligne de commande pour Linux et Windows ; l’application macOS et l’APK Android s’installent à la main). varsto update seul reste sur les versions officielles et n’installe jamais une version quotidienne.
  • Conservez vos propres sauvegardes.

Vous cherchez quelque chose de fiable ? Utilisez plutôt les téléchargements stables.

Vérifier

Placez SHA256SUMS à côté des fichiers téléchargés (les noms du tableau sont les noms fixes) et exécutez

sha256sum -c SHA256SUMS --ignore-missing

Omettez --ignore-missing si vous avez téléchargé tous les fichiers. La liste est signée avec la clé quotidienne distincte (SHA256SUMS.sig, format minisign ; la clé est daily-key.pub), ce que vérifie varsto update --daily. Outre l’intégrité du téléchargement, la signature montre que la liste provient de la chaîne de construction du projet.
