All comparisons

Varsto and Resilio Sync

Resilio Sync syncs and shares folders between devices peer to peer, built on BitTorrent technology. The free Sync Home edition is for individuals; the company's main business is enterprise file transfer. Resilio was acquired by Nasuni in March 2026.

Where Varsto differs

  • Source-available, with a published storage format: your data stays recoverable without the vendor.
  • Hybrid post-quantum cryptography for every stored signature and every sealed key (designed for; not audited).
  • Your storages are the always-available copy, so no always-on peer is needed; devices still exchange blocks directly when they can reach each other.
  • A signed ledger counts and verifies every copy, and durability policies warn before a rule breaks.
  • No vendor trackers or relays: devices find each other through your storages and on the LAN, and relay through one of your own devices when NAT cannot be punched.

How Resilio Sync works

Devices connect directly; there is no account, and folders are shared with keys or links (read-only or read-write). Resilio-run trackers and relays help peers find each other. Data lives on the peers only; Sync Home has no S3 or rclone backend. Selective sync with placeholder files is available, and an "encrypted folder" lets a peer on an untrusted machine store data it cannot read (that peer is read-only and has no selective sync).

Measured against Resilio Sync (November 2026)

On 10 November 2026 both tools moved the same data between the same three rented machines (a writer in Paris, readers in Amsterdam and Warsaw, 2 vCPU each), one tool at a time, with relays and trackers off, and every file was checked by SHA-256 afterwards. Varsto was the daily build 20261109-c1cf5c2; Resilio Sync was 2.8.1, because 3.1.2 did not sync from a configuration file at all. Medians of two runs. "Bytes" is what the reader exchanged with the other machines. The method, its limits, the raw data and the scripts to repeat it are in the measurement report.

  • Two readers finished together in about two minutes with both tools. Warsaw was the slow one. The writers sent about 3.6 GB each.

One day, one provider, two runs per case, and an alpha: these are indications, not a verdict. The report lists everything that limits them.

Neither tool was clearly faster. The medians are 25 s for both. Resilio Sync moved 313 MB and Varsto 292 MB, and neither run stalled. Ten thousand small files still means a request per file: Varsto asks for each encrypted block on its own, so the handshake can cost more than the bytes, while Resilio Sync keeps many pieces moving with less setup per file. On this day that difference did not decide the clock.

Varsto was faster, 44 s against 90 s, and both tools moved about 2.2 GB. The files are large, so the link is the limit, not the per-file setup. Varsto keeps the connection to the peer open and has many block requests in flight, so the link stays full. Resilio Sync took longer to move the same two files on this path.

Varsto was faster, 17 s against 47 s, because it compresses each block before encrypting it. Log text shrinks, so about 169 MB cross the link instead of 563 MB. Resilio Sync sends the text as it is stored.

Varsto was faster, 13 s against 62 s, because half of the files are copies of the other half. Those blocks are already on the reader's disk, and Varsto reuses them instead of downloading them again. Resilio Sync sends the copies a second time, so it moves about 856 MB instead of 419 MB.

The slower reader finished in about 118 s with both tools. Amsterdam was quicker than Warsaw for both. Each writer sent about 3.6 GB. Two readers pulled the same large files at once, and bytes also moved between the readers, so the writer's total is more than one copy of the files.

Resilio Sync's figure is from 8 November, while this case is being run again. Then it finished in 15 s and moved 12 MB: it sends the changed piece and stops. Varsto's one counted run on 10 November moved 26 MB in 12 s. Varsto also transfers only the changed blocks, but the writer syncs every folder it holds and the reader re-hashes blocks it already has, which can cost more than the transfer. The other Varsto run moved nothing and was not counted.

Resilio Sync's figure is from 8 November, while this case is being run again. Then it treated the new directory as new data and sent it again, 67 s and 1 269 MB. Varsto's rename on 10 November finished in 10 s and the reader pulled no file data: a rename is a new name for blocks already stored, and Varsto moves the local files.

The reader's link was held at 100 Mbit/s, with 40 ms of delay and 1% of packets dropped at random, and it was cut on purpose for 0.3 seconds every 4 seconds. Packets in the air during a cut disappear, and TCP waits and sends them again. The small files barely compress, so both tools moved about 330 MB. Varsto finished in 432 s and Resilio Sync in 934 s. Which one fits

Resilio Sync

Choose Resilio Sync when you want fast BitTorrent-style transfer between always-on machines and easy sharing by key or link, and a closed-source vendor product is acceptable.

Varsto

Varsto's peer-to-peer transfer is modelled on the same idea (encrypted blocks from several peers at once), but it adds your own storages as the always-available copy, a record of where every copy is, durability policies and an open specification of the formats.

Varsto is alpha software: do not trust it with data you have no other copy of, and its cryptography has not been independently audited. The other products here are mature. Facts about them were checked from their own documentation in October 2026; prices and plans change often, so see their own pages for current figures. Corrections are welcome as GitHub issues.
