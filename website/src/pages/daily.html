Daily builds

These are development builds from the main line, not releases.

  • They are not releases and have not been through release testing. They carry no release signature and no Apple or Microsoft code signing. Do not use them for production data.
  • The storage format can change from one build to the next without any migration. These builds write storage format 3: a vault made by 0.0.1-alpha.15 or earlier is refused and has to be recreated (varsto reset --yes, varsto init, then sync the files again), and 0.0.1-alpha.15 refuses a format 3 vault. A device that joins asks for each folder and an owner approves it; varsto init prints a second set of 24 recovery words that varsto folder add asks for.
  • varsto update --daily installs the latest daily build for your platform (the Linux and Windows command-line builds; the macOS app and the Android APK are installed by hand). Plain varsto update stays on releases and never installs a daily build.
  • Keep your own backups.

Looking for something to rely on? Use the stable downloads instead.

Verify

Put SHA256SUMS next to the files you downloaded (the file names are the stable ones in the table) and run

sha256sum -c SHA256SUMS --ignore-missing

Leave out --ignore-missing if you downloaded every file. The list is signed with the separate daily key (SHA256SUMS.sig, minisign format; the key is daily-key.pub), which is what varsto update --daily checks. Besides telling you that a download is complete and intact, the signature shows that the list came from the project's own build.
