One package per platform with the background service, the interface and the same command line inside; on Linux and macOS the service starts at login (a systemd user unit or a launch agent), on Windows the tray app runs it. On Linux and Windows the interface opens in your browser; on macOS the native app has its own window. Alpha: use it with test data only and keep your own backups.

Android. The APK is signed for release under a new key, so later releases install over it as an update. An earlier debug APK (alpha.15 or an older daily build) cannot be updated to it: uninstall the old app first, which removes that device's copy of the vault, so make sure the vault has another device or a storage, then install the new APK.

iOS: unsigned ipa, AltStore, SideStore and Sideloadly

The iOS package is an unsigned .ipa. It does not install from the file alone. AltStore, SideStore or Sideloadly sign it with your own Apple ID and install it. Varsto does not have an Apple developer signature. A Sideloadly error about signing, an Apple ID that cannot sign more apps, an expired sideload, or a device that does not trust the developer comes from that tool or from Apple, not from a broken package. The same file is what those tools install. The app has been built in CI and has not been run on a real device yet. The source of the shell is in apps/ios on GitHub.

The alpha is not in an app store. Check the file against the checksum list signed with the release key. Apple and Microsoft code signing is not in place yet, so macOS and Windows warn on install. The Android package is signed with the project's own key.

Install and verify

curl -O https://varsto.net/downloads/SHA256SUMS
curl -O https://varsto.net/downloads/varsto-{{VERSION}}-x86_64-unknown-linux-musl.tar.gz
sha256sum -c SHA256SUMS --ignore-missing
tar xzf varsto-{{VERSION}}-x86_64-unknown-linux-musl.tar.gz
cd varsto-{{VERSION}}-x86_64-unknown-linux-musl
./varsto desktop        # opens the desktop interface in your browser
./varsto --help         # command line

Build from source

The source lives at github.com/janttsu/varsto; every release is a tag there with the same files attached to its GitHub release, and the source archive below matches it. With a stable Rust toolchain (1.85 or newer): git clone https://github.com/janttsu/varsto.git or unpack the archive, then cargo build --release; the binary is target/release/varsto. cargo test --workspace runs the test suite, including the two-device scenarios.

Desktop interface

On Linux and Windows the default is varsto tray: a tray icon with open and pause, and an install item when a newer version exists; the background service syncs changes within seconds on its own. varsto desktop starts a small web server bound to 127.0.0.1 on a random port, prints a one-time link with a session token and opens it in your default browser. Only programs on this computer can reach it; the page refuses requests without the token and requests whose Host header is not the local address. From the interface you can create or join a vault, add storages and folders, share, set policies and list duplicates; sync, verification and repair run on their own. The app bundle and Varsto.cmd do exactly this.

Quick start (command line)

export VARSTO_PASSPHRASE='a long passphrase'
varsto --home ~/.varsto-laptop init --name laptop            # prints the vault key once; keep it offline
varsto --home ~/.varsto-laptop storage add-local box /mnt/box
varsto --home ~/.varsto-laptop folder add docs ~/Documents/synced
varsto --home ~/.varsto-laptop sync

# another device that can reach the same storage
varsto --home ~/.varsto-desk join --name desk --vault-key <hex> --storage-path /mnt/box
varsto --home ~/.varsto-desk folder attach docs ~/synced
varsto --home ~/.varsto-desk sync
varsto --home ~/.varsto-desk status --json
varsto --home ~/.varsto-desk fsck --verify

The vault key is the master key in hex. Losing it and every device means losing the data: there is no account and no escrow.
